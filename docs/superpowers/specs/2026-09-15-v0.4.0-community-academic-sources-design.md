# Follow-up v0.4.0 社区与学术来源设计

更新日期：2026-09-15  
状态：已批准，待实施

## 目标

v0.4.0 在现有本地 Acquisition Runtime 上新增 GitHub、Hacker News、Reddit、
Techmeme、arXiv 与 Hugging Face Papers 六类 Adapter。所有来源继续输出临时 Signal，
不直接写入正式 Knowledge；新来源先进入 shadow 和来源级迁移门禁，不因代码就绪自动替换
中心 Feed。

本版优先使用公开 HTTP、JSON、RSS/Atom 页面或接口，不提前引入 v0.5.0 的 managed local
tools。GitHub 的可选 Token 用于提高公开数据限额及显式启用 Discussion 子流；Reddit 仅实现免
Key 路径，不实现 OAuth、全站评论搜索或付费数据后端。

## 权威性与旧计划覆盖

本文是 v0.4.0 的版本级权威设计；与 2026-09-02 采集母计划冲突时，以本文为准。旧计划仍用于

## 范围

### 本版包含

- GitHub：公开仓库、Release、Commit、Issue、Pull Request 与可选 Discussion 的发现证据；支持无凭据运行，
  可选凭据引用用于提高公开 REST 限额，并在显式配置时启用 Discussion。
- Hacker News：新帖、热门帖和主题搜索，保留 story ID、points、comments 与排名。
- Reddit：预置社区的公开 RSS/列表入口，保留 post ID、score、comment count 与 subreddit；
  页面或接口不可用时明确失败，不静默切到需要凭据的路径。
- Techmeme：公开首页/归档的聚类与条目发现，保留 cluster/post 身份和页面时间语义。
- arXiv：现有六个分类来源的本地 Adapter，读取官方 RSS/Atom API，显式使用发布时间和更新时间，
  按请求窗口过滤并按配置 budget 截断。
- Hugging Face Papers：一个来源覆盖 Daily、Trending、ISO Weekly 三视图，沿用
  `2026-09-14-hugging-face-papers-source-design.md` 的完整契约。
- Candidate Feed、curation request、selection、artifact、renderer、manifest 与 active state 对
  `communityEvidence` 的端到端支持。
- 正常、空结果、限流、超时、结构漂移、部分失败、分页、重复和日期边界 Fixture。

### 本版不包含

- X、YouTube 转录、播客转录、Digg、微信公众号、小红书或认证 Sidecar。
- managed CLI 安装、自动安装依赖或全局包管理器变更。
- Reddit OAuth、评论全文搜索、用户私有数据或付费 enrichment。
- 基于热度直接淘汰论文；热度只能成为社区发现和影响力判断证据。
- 中心 Feed 下线。来源切换仍须通过既有 14 天、3 次真实运行和人工相关性门禁。

## 架构

### 1. 公共 HTTP 客户端

新增 `src/follow_up_acquisition/http_client.py`，供六类 Adapter 共用：

- 只允许 HTTPS；arXiv 官方 API 如仍返回文档所述 HTTP self-link，只把它当元数据，实际请求
  使用配置中的 HTTPS endpoint。
- 每个 Adapter 声明固定 host allowlist；重定向后重新校验 scheme、host、公共地址和路径。
- 统一 User-Agent、连接/读取超时、响应体上限、JSON/XML/text 解码和可注入 `fetch`。
- 429 或明确 rate-limit 响应映射为 `rate-limited`；超时、网络错误、非预期 schema 分别映射为
  `timeout`、`unreachable`、`schema-drift`。
- 记录 `ETag`、`Last-Modified` 和安全的分页 cursor；不记录 Authorization、Cookie 或完整响应头。
- 重试只处理尚未收到应用层响应的瞬时网络错误，最多一次；收到 429 后不在同一运行中重试。

### 2. 增量状态

新增 `src/follow_up_acquisition/source_state.py`，在
`~/.follow-builders/acquisition/source-state/<source-id>.json` 保存：

- schema version、source ID；
- `streams` 对象；key 是 Adapter 定义且通过 `^[a-z][a-z0-9._-]{0,63}$` 的稳定子流 ID；
- 每个子流分别保存最后成功窗口结束时间、安全 cursor、ETag、Last-Modified、最近成功原生 ID
  水位集合（最多 500 项）、可选 `query_fingerprint`、由 store 管理的可选 `inactive_since` 和
  checkpoint 时间；
- `updated_at`。

Registry 中每个 GitHub/HN 查询对象必须带不可变、来源内唯一且匹配
`^[a-z][a-z0-9-]{0,31}$` 的 `id`；查询顺序或显示文本变化不改变 ID，改变查询语义时必须分配新 ID。
子流 ID 固定为 GitHub `query.<query-id>` / `discussions`、HN `top` / `new` /
`search.<query-id>`、Techmeme `front` / `archive`、arXiv `rss` / `metadata`、HF `daily` /
`trending` / `weekly`。cursor 只能在所属子流复用。

Techmeme `archive` checkpoint 内保存当前处理日期和最近 14 个完整日期的有序集合，不为每个日期新增
stream key。外部 update 允许临时携带最多 15 个日期，必须先完整验证所有日期，再在提交时删除最早
日期；持久状态始终不超过 14 个。查询配置首次移除时由 store 写入 `inactive_since`，stream checkpoint
从该时间起保留 7 天以支持回滚，之后才删除；重新启用或成功更新会清除 `inactive_since`。

GitHub/HN 查询子流必须保存 `query_fingerprint`。算法为 SHA-256 over 现有 `frameFields` 的
length-prefixed UTF-8 fields，顺序固定为 `query-v1`、adapter ID、query ID、规范化 query、sort、
规范化 filters。query 只做首尾去空白和连续 Unicode whitespace 折叠；sort 使用固定枚举值；filters
按 Adapter 定义的字段名顺序编码，集合值按 UTF-8 bytes 排序后以 JSON 数组编码，数字使用十进制，
缺失值编码为空字符串。显示 label、配置数组位置和注释不参与指纹。同 ID 的指纹不匹配时拒绝复用
checkpoint 并返回 `schema-drift`，不能静默重置水位；合法语义变更必须使用新 query ID。

状态以来源为单位原子写入。子流成功或完整空结果才可提交该子流 checkpoint；失败页及其后续页不得
推进。来源为 `partial` 时只提交本次已完整结束的其他子流，失败子流保持旧 checkpoint，下一次从旧
checkpoint 重试。其他失败不推进任何子流。合并时逐子流执行 compare-and-swap：磁盘 checkpoint
时间比本次读取版本更新时拒绝覆盖并报告 `state-conflict`，不影响已发布 batch。

状态文件严格关闭字段、最大 256 KiB 并拒绝凭据形状与高置信 credential value，包括 `github_pat_`。
query/filter 字符串只折叠冻结的 Unicode White_Space，其他 C0/C1/DEL 控制字符直接拒绝。Adapter 接收
只读 checkpoint，仍不直接写盘。
`SourceResult` 新增不序列化到 Signal Batch 的 `checkpoint_updates`，每项为严格的
`{stream_id, previous_checkpoint_at, checkpoint}`。Runtime 校验 source/stream、字段白名单、大小和
凭据后生成 pending updates。Python 生成的 intent 先由 Node 验证，再与 batch 一起写入不可变 run；
`run.json` 记录 intent SHA-256。CLI 的时序固定为：收集 → 构建并验证全部 batch/intent → 原子发布
本次 run → 发布全部 latest pointer → 以 published intent 路径、expected digest 和 run ID 逐来源 CAS
提交 checkpoint。Python 必须在同一已打开文件句柄上重算 digest 并重验 run ID。batch/run/pointer
发布失败时不提交状态；checkpoint 提交失败时 batch 保留，但本次
命令返回 `partial` 运维结果，后续依靠 native ID 去重安全重读。

v0.4 的持久来源状态仅在已验证的 macOS/Linux 上启用。调用方必须先安全创建权限 0700 的直接父目录
`~/.follow-builders/acquisition/`；state store 不创建缺失祖先。在该父目录中持久保留一个 0600、单链接、
`O_NOFOLLOW` 打开的 `.source-state.init.lock`，只序列化 `source-state/` 叶目录首次创建并 fsync 父目录项；
leaf 固定后释放 init flock，但保留 pinned init-lock fd 到事务结束供身份复核。不同来源随后只由各自的
source lock 串行化，可并发运行。
之后锁、状态、临时文件、rename 与 fsync 都相对同一可信 leaf dirfd 完成；父目录与 leaf 的身份定义为
nofollow parent-entry 和 pinned fd 的 directory type、dev/ino、mode/private 一致，允许无关子项引起的
directory `nlink` 变化；init lock、source lock、temp 和 state 普通文件仍要求单链接。上述身份在发布
前后复核。rename 后目录 fsync 失败
返回 `state-durability-uncertain`，调用方必须重读而不得自动重试。Windows 缺少已验证的 reparse-point
与 handle-based backend，本版在 local/shadow/hybrid 模式 fail closed 为 `unsupported-platform`；central
模式、安装和现有中心 Feed 继续可用。其他 POSIX 与 Windows 本地状态后端须单独验证目录 hardlink、
路径身份与锁语义，并通过对应 adversarial CI，
不得使用普通字符串路径或仅 `msvcrt.locking` 冒充同等安全保证。

### 3. Adapter 边界

每个 Adapter 实现既有 `availability_probe`、`validate_request`、
`collect(source, request) -> SourceResult` 协议，只产生 `SourceCandidate`。Runtime 继续独占：

- batch ID 与生成时间；
- 来源内 native ID / canonical URL 去重；
- Signal Batch 校验；
- 来源失败隔离和状态序列化。

所有 Adapter 构造器接受 `resolve_source`、可注入的 HTTP client 和 clock，Fixture 测试不访问网络。
budget 在解析、去重和窗口过滤之后应用；同分时使用发布时间降序、native ID 升序，保证确定性。

## 各来源采集语义

### GitHub

- 无凭据走公开 REST API；可选 Token 在首个请求前只解析一次，与 Discussion 开关无关，用于提高 REST
  限额并在显式启用时访问 GraphQL。Token 绝不进入 request、batch、日志或状态；解析失败时零网络、
  固定 `auth-failed`，Token 被拒绝后不回退匿名。
- 查询由 registry 的 `queries` 数组提供，不把用户兴趣拼进任意 URL；页码、每页数量、排序字段和
  host 固定在 Adapter 内。
- GitHub identity 统一使用带实体类型的 GraphQL node identity：REST 响应读取同一对象的 `node_id`，
  GraphQL 响应读取 `id`，规范化为 `github:<entity-type>:<node-id>`。Repository、Release、Issue、
  PR、Discussion 分别使用固定 entity type。缺少合法 `node_id`/`id` 的条目不允许以数字 ID fallback，
  该条目被丢弃并记录 `github-node-id-missing` warning；若入口所有条目均因此无法解析，则入口为
  `schema-drift`。provenance 记录父仓库 identity 与查询。
- Commit identity 使用 `github:commit:<repository-node-id>:<lowercase-sha>`；只采集配置查询或已发现
  仓库窗口内的 Commit，
  不进行全 GitHub Commit firehose。
- `native_metrics` 可含 stars、forks、watchers、comments、reactions、open/closed 状态和原生更新时间。
- `include_discussions` 默认 `false`。没有可选 Token 时 REST 匿名运行；显式启用 Discussion 但 Token
  缺失时不发 GraphQL，REST 仍可运行，来源为 `partial`。
- Token 无效或被撤销且所有已启用入口都拒绝为 `auth-failed`；REST 成功但 Discussion 缺权限为
  `partial`；所有
  已启用入口额度耗尽为 `rate-limited`；部分查询成功、其他查询限流为 `partial`。配置了 Token 后不
  静默回退到匿名请求，确保失效凭据可见且不产生双重额度语义。

GitHub 所有网络调用必须通过一个共享 executor。匿名模式每次运行固定上限为 total 24、Search 9、
core REST 15、GraphQL 0；Token 模式为 total 64、Search 27、core REST 31、GraphQL 6。`budget` 只限制
最终候选，不能放大网络上限。请求按 `(query_id, endpoint, phase)` lane 的 UTF-8 稳定顺序 round-robin，
`scheduler` checkpoint 保存 lane-set fingerprint 与 next index；一个 lane 在其他 eligible lane 获得
机会前不得连续消费第二个 quantum。预算耗尽是可恢复的 `partial/github-request-budget-exhausted`。

一个 quantum 精确等于一次 HTTP 调用，包含 Search、parent lookup、Release page 与 GraphQL page。
只为 query `filters.entities` 明确启用的 entity 创建静态 lane：`repository-search`、`commit-search`、
`issue-search`、`pull-request-search`；`release` entity 创建 `release-roster` 与 `release-poll`，但同一
query/window 无 roster 时只允许 roster，有未完成 roster 时只允许 poll；启用 Discussion 才创建
`discussion-search`。parent lookup 与 Release parent/page 是所属静态 lane 的内部 phase，不动态新增
lane。lane ID 为 `<query-id>.<lane-kind>`，按 UTF-8 bytes 排序。scheduler stream ID 固定为 `scheduler`，cursor 精确为
`{lane_set_fingerprint,next_lane_id}`；fingerprint 使用 `frameFields(["github-lanes-v1", ...laneIds])`
的 SHA-256。成功、lane failure 或预算 quantum 后 next 指向排序后的下一个 lane；打开全局 breaker
且本次无成功时不得提交 scheduler checkpoint，下一次在外部限额/凭据恢复后重试同 lane，符合失败
SourceResult 不推进状态的 Runtime 契约。lane set 因合法 query 增删变化时，scheduler
以固定 warning 重置到新集合第一项并提交新 fingerprint；同 ID 语义变化仍由 query fingerprint 拒绝。
active streams 始终包含 `scheduler` 与全部 `query.<id>`；`include_discussions=true` 时再包含
`discussions`，关闭或移除的 stream 进入 Foundation 的 7 天 inactive 生命周期。

REST 429/明确额度耗尽打开全局 rate breaker；Token REST 401/403 与 GraphQL `UNAUTHENTICATED` 打开
全局 auth breaker，后续请求全部停止；GraphQL scope/permission 只停止 Discussion。已有成功候选与
子流 checkpoint 保留，失败 lane 不推进。无任何成功时分别使用 `rate-limited`/`auth-failed`，已有成功
时为 `partial`。

HTTP 分类顺序固定：429 一律 rate；403 满足以下任一可信指标即 rate：合法 `Retry-After`、
`X-RateLimit-Remaining` 精确为 `0`、JSON `code` 精确为 `rate_limited` / `secondary_rate_limit` /
`abuse_detected`。否则 Token 请求的 401/403 判全局 auth，匿名 401/403 判 lane
`error`。GraphQL error 数组优先级为 rate → `UNAUTHENTICATED` 全局 auth → `FORBIDDEN`/scope
Discussion-only → validation/bad-input schema-drift → internal/unknown error；只要有 errors 就不消费 data。
“已有成功”指本次至少一个请求返回并通过完整 schema，即使候选为空；breaker 前无成功用其根状态，
有成功统一为 partial。预算耗尽无论候选数都为 partial，不冒充 upstream error。

可选凭据引用只存在用户配置 `acquisition.sourceCredentials["community:github"] =
{"ref":"env.GITHUB_TOKEN"}`，不进入 Registry。credential resolver 精确返回关闭的 tagged object：
`{"status":"absent"}`、`{"status":"resolved","token":"..."}` 或
`{"status":"resolution-error"}`；其他形状 fail closed。resolved token 必须是 exact string、1–4,096
Latin-1 bytes、无 C0/C1/DEL、无首尾 whitespace 且可直接作为 Authorization header value；不满足时
按 resolution-error 零网络处理。absent 使用匿名 REST；Discussion 启用时追加缺凭据 partial。resolution-error 零网络并
返回固定 auth-failed；resolved token 被拒绝打开全局 auth breaker，不匿名 fallback。

Release discovery 先以不含 `pushed`/时间窗 qualifier 的 Repository Search 冻结最多 100 个相关 repo
roster，再按 `repo_index`/`release_page` 分 lane 轮询公开 Releases API；Release 返回后才按 canonical
window 过滤。roster、cursor、repo identity 严格有界且去重，请求预算耗尽后下次从 parent/page 继续，
不得重新 fan-out。

roster discovery 精确发一个 `per_page=100&page=1` Repository Search，请求必须完整且
`incomplete_results=false`；不完整时不得 fan-out。roster 项关闭为 `{name_with_owner,node_id}`，各字段
有界，按 Search 返回顺序 first-wins 去重，最多 100；fingerprint 精确使用
`frameFields(["github-release-roster-v1", rosterCountDecimal, name1, node1, ...])`。cursor 只有两个关闭
变体：`{phase:"discover",window}`，或 `{phase:"poll",window,roster,roster_fingerprint,repo_index,
release_page,counters}`；repo_index 为 0..roster.length-1，release_page 为 1..100，counters 的每个
非负整数上限 10,000。counters 关闭且全部必填：`roster_total`、`repos_completed`、`pages_fetched`、
`releases_seen`、`releases_in_window`、`node_missing_seen`、`valid_seen`；`roster_total == roster.length`、
`repos_completed == repo_index`、in-window/valid/node-missing 不得大于 seen。空 roster 直接完成 Release
endpoint，不生成 poll cursor。release-poll 每 quantum
只读取当前 parent 一页；预算/breaker 后保存当前 index/page，下次不重新 discovery。所有 parent 完成
后清空 cursor、推进 window，下个 window 才刷新 roster。`total_count>100` 表示有意采用 top-100 bounded
roster，不视为错误，但写固定 coverage warning。

Releases list 响应必须是 exact array、最多 100 项；短页或空页完成当前 parent，满 100 项才递增 page。
第 100 页仍满时以 fixed coverage warning 完成该 parent，绝不产生 page 101。只有当前 parent 完成才
递增 repo_index；预算或 breaker 保留原 index/page。

Window 只允许省略/null 自动增量，或显式完整 `{start,end}`；空对象/单字段拒绝。`start` 可 null，
`end` 可 null（采集开始时冻结 clock.now），合法 offset 统一转 UTC 秒精度 `Z`；start 不得晚于 end。
resume 必须逐字复用 checkpoint window。REST Search 严格验证非负 `total_count`、boolean
`incomplete_results` 与 items 上限。Repository/Commit `per_page=100`，Issue/PR `per_page=10` 并把最多
10 个待 parent lookup 项有界保存在 endpoint cursor。pending 项只允许关闭投影
`{node_id,url,title,author,published_at,updated_at,comments,reactions,state,repository_api_url}`，单字段沿用
candidate 上限、单项 JSON 最多 4 KiB、数组最多 10 项且总计最多 40 KiB，禁止任何原始 Search payload
未知字段。pending 十个字段全部必填：node/url/title/author/repository URL 为有界非空 string，两个时间
为 canonical UTC string，comments/reactions 为 0–1,000,000,000 integer，state 只能 open/closed。
endpoint cursor 关闭为 `{phase,window,page,expected_total_count,counts,pending,next_page}`；phase 只能
`search` 或 `parent-lookup`，page/next_page 为 1..10，expected total 为 0..1,000,000,000，counts 复用
`entries_seen/node_missing_seen/valid_seen` 三个有界非负整数；parent-lookup 必须有 1–10 pending，search
必须 pending 为空。Search page 在 pending 全部成功 lookup/明确丢弃前不得前进；一次 parent lookup
是一个 quantum。timeout/unreachable/rate/auth/非 404 HTTP 与 parent payload schema drift 保留当前项和
page 供重试；明确 404 或合法 parent payload 缺 node ID 丢弃当前项并写固定 warning。只有 pending
清空才把 page 设为 next_page；不存在其他“明确丢弃”路径。首页冻结 `total_count`；后页必须完全相等，变化
时固定 partial 并重置同 window page 1，依靠 recent IDs 去重。短/空页只有在累计数达到
`min(total_count,1000)` 时可完成，否则同样 snapshot-changed reset。优先级为 HTTP breaker → envelope
schema → incomplete_results partial → snapshot consistency → page10 cap → request budget。page10 且
total_count>1000 时以 partial/cap 完成本次 bounded top-1000、推进该 endpoint window，绝不产生 page11。
GraphQL `nodes` 必须不超过请求 `first<=100`；`pageInfo.hasNextPage` 为 exact bool，true 时 endCursor
必须非空、有界且不同于输入，false 时 endCursor 只可 null 或有界 string。当前响应与已持久 cursor 均
拒绝重复 cursor。GraphQL errors 优先于 data，出错时不映射 nodes、不推进 checkpoint。

Discussion checkpoint 保存 query-set aggregate fingerprint：对排序后的 `(query id, authoritative query
fingerprint)` 与 GraphQL template version 使用 length-prefixed SHA-256；query reorder 稳定，语义增删改
在 POST 前拒绝旧 cursor。`scheduler` 与 Discussion aggregate fingerprint 都属于 active stream。

Discussion stream ID 固定为 `discussions`，字段名固定 `query_set_fingerprint`，template 常量固定
`github-discussions-template-v1`。哈希精确为 SHA-256 of
`frameFields(["github-discussions-v1", "github-discussions-template-v1", queryCountDecimal,
queryId1, queryFingerprint1, ...])`，query pair 按 query ID UTF-8 bytes 排序。resume 不匹配时零 POST、
schema-drift 且不改旧 cursor；关闭 Discussion 时该 stream inactive。

模块依赖单向：`github_models.py` 只定义 Window、RequestBudget、Breaker、LaneOutcome 与严格 state
dataclass；`github_scheduler.py` 只依赖 models，负责 lane/fingerprint/round-robin；`github_queries.py`
是无 I/O 纯 query/hash 模块；`github_mapping.py` 是无 I/O payload→SourceCandidate 映射；
`github_executor.py` 依赖 models 与 HttpClient，唯一拥有 budget buckets、breaker 与“一次调用一个
quantum”的 `execute(request_kind, call)` API；
`github_rest.py`、`github_releases.py`、`github_discussions.py` 只通过 executor 发请求并返回 typed
LaneOutcome，不直接修改共享状态；`github.py` 作为薄 facade 负责依赖注入、凭据三态、调度和最终状态/
checkpoint 聚合。低层模块不得反向 import facade，executor/scheduler 必须可独立单测。

### Hacker News

- 官方 Firebase API 提供 top/new item identity 与条目详情；Algolia 只承担有时间窗口的主题搜索。
- identity 为 HN item ID；只把 story 作为候选，评论用于受限 enrichment，不单独形成候选。
- `native_metrics` 保存 points、descendants、列表位置；provenance 保存入口类型与查询。
- 任一入口失败而其他入口成功（无论成功入口有无候选）时为 `partial`；全部入口成功且无候选为
  `no-results`。

### Reddit

- 每个 source 绑定一个固定 subreddit，优先 RSS，允许同一 subreddit 的公开 listing JSON 作为
  兼容回退；不绕过登录墙、robots、访问控制或速率限制。
- identity 使用 fullname/post ID；保留 canonical comments URL、outbound URL、score、upvote ratio、
  comment count、flair 和列表位置。
- RSS 成功但缺少部分指标仍可产出候选并添加 warning；所有免 Key 路径失败则按实际原因返回失败。
- 不抓取用户资料、删除内容、私有社区或评论全文。

### Techmeme

- 固定读取公开首页和请求窗口内的日期归档；不使用任意站内搜索。
- cluster identity 优先页面稳定锚点，缺失时使用规范化 lead URL 与归档日期的确定性组合。
- 主条目与 related links 保存在同一候选 provenance；原始发布链接优先作为候选 URL，Techmeme 页面
  URL 作为发现证据。
- 页面可访问但布局无法识别为 `schema-drift`；部分归档失败为 `partial`。

### arXiv

- 分类日更优先读取 registry 中现有 RSS；需要补齐摘要、作者或更新语义时，按 ID 批量调用官方 Atom
  API，不为每篇论文单独请求。
- 统一 identity 为去版本号、转小写的 `arxiv:<id>`；canonical URL 使用 HTTPS abstract page。
- `published_at` 表示首版提交时间；更新时间写入 `native_metrics.updated_at`，版本号单独保存。
- 请求窗口使用更新时间判断“本次新信号”，首版时间仍保留给策展。结果显式按
  `updated_at desc, native_id asc` 排序，再按各来源 budget 截断。
- 相关性仅以配置关键词和候选 title/abstract 计算；不使用引用数、下载量或虚构热度。连续 API 请求
  遵守官方建议的间隔，日内相同查询使用缓存。

### Hugging Face Papers

- 来源和三视图语义完全沿用既有 HF-1 设计：运行时区生成 Daily 日期和 ISO Weekly，Trending 无日期。
- 优先消费 Hugging Face 正式结构化 Papers 接口；页面 URL仍写入 provenance，供用户核验。
- 同一论文跨视图以标准化 arXiv ID 合并；没有 arXiv ID 时以 HF paper ID，最后才用 canonical URL。
- 三视图固定顺序为 daily、trending、weekly；每类只保留第一个合法视图证据。
- 全部成功有结果为 `ok`，全部成功为空为 `no-results`，成功与失败混合为 `partial`，全部失败为
  `error`。具体失败原因放在安全的视图状态中。

## 热度、相关性与社区证据

采集阶段不设置跨平台统一热度阈值。原因是 star、HN points、Reddit score 和 HF upvotes 不可直接
比较，且早期内容天然分数较低。Adapter 只做以下确定性工作：

1. 先按时间窗口、来源身份和配置主题过滤；
2. 保存平台原生指标及采集时刻；
3. 在单一入口内部需要截断时，使用该平台的原生顺序，再以时间和 native ID 稳定消歧；
4. 把热度交给策展阶段的 impact/relevance/novelty 判断。

`communityEvidence` 只表示社区发现或热度，不表示事实交叉印证。它是严格 `oneOf`：

1. HF 变体保持 HF-1 已冻结的精确形状：`role`、非空 `views` 和可选 `github`；
2. 通用社区变体为
   `{role, platform, pageUrl, metrics}`，其中 `role` 固定为 `community-discovery`，`platform` 只能是
   `github` / `hacker-news` / `reddit` / `techmeme`，`pageUrl` 是最长 1,024 字符的允许来源 HTTPS
   URL，`metrics` 为 1–8 个严格关闭对象 `{kind, value}`。`kind` 只能是 `stars`、`forks`、
   `points`、`comments`、`score`、`upvote-ratio`、`rank`、`reactions`，每类最多一次并按该枚举顺序
   输出；`value` 是 0–1,000,000,000 的有限 number。

两种变体 JSON 序列化后均不得超过 4,096 bytes。映射层省略非法单项；若最终无合法 evidence 或
整体仍超限，则保留候选但省略 `communityEvidence` 并记录固定 warning。含合法
`communityEvidence` 的非 lead 候选必须进入 `communityEvidenceCandidateIds`，不得进入
`corroboratingCandidateIds`。混合 cluster 的 lead 必须来自无该 role 的官方/原始候选；只有 cluster
全部是社区候选时才允许其中一个成为 lead，其余仍进入 `communityEvidenceCandidateIds`。社区 lead
是唯一的 role/位置例外，其摘要必须明确是社区发现，不能冒充官方事实。

## 下游契约升级

沿用 HF-1 设计并一次完成以下 1.1 升级：

- Candidate Feed candidate 和 curation request candidate 新增可选、同构、严格关闭的
  `communityEvidence`。
- digest-selection `schemaVersion` 升为 `1.1`；cluster 新增必填
  `communityEvidenceCandidateIds`。
- 每个 eligible candidate 必须且只能是 lead、corroborating 或 community evidence 三者之一。
- `eventClusterId` 用三类成员并集重算。
- `corroboration` 仅按 lead 与 corroborating 中不同 source ID 数量确定：少于 2 个为 0，2 个为 4，
  3 个为 7，4 个及以上为 10；社区成员完全排除。
- Digest artifact `schemaVersion` 升为 `1.1`，每项新增必填 `communityEvidence` 数组。
- renderer 最多展示 3 项并使用“社区热度”；剩余显示“另有 N 项社区证据”，不得写“交叉印证”。
- generation manifest、active state 和 delivery candidate IDs 收集三类成员完整并集。

Signal Batch 仍保持 `1.0`，因为 `native_metrics` 与 `provenance` 已能承载来源原生信息；Node 消费层
按 source adapter 只从白名单形状映射对应 evidence 变体，不透传未知键。

## 错误与状态

| 情况 | 来源状态 |
|---|---|
| 所有必需入口成功且有候选 | `ok` |
| 所有必需入口成功且无候选 | `no-results` |
| 至少一个入口成功、至少一个失败 | `partial` |
| 429 或明确额度耗尽 | `rate-limited` |
| 连接或 DNS 失败 | `unreachable` |
| 连接/读取超过预算 | `timeout` |
| 可访问但 payload/布局不符合契约 | `schema-drift` |
| 其他已隔离错误 | `error` |

`no-results` 只能来自完整成功检查。`partial`、`rate-limited`、`unreachable`、`timeout`、
`schema-drift` 和 `error` 不得被摘要为“没有更新”。错误消息只保留固定 endpoint label、HTTP status、
安全 retry hint 和视图名，不回显查询中的潜在私人内容或本地路径。

HF 是多视图聚合的显式例外：顶层只使用 `ok` / `no-results` / `partial` / `error` 四态；三个视图全部
失败时顶层固定为 `error`，各视图在内部状态中保留 `rate-limited` / `timeout` / `schema-drift` 等具体
原因。HN、GitHub、Techmeme 的“一个入口完整空结果、另一个入口失败”统一为 `partial`。

### 真实 smoke
