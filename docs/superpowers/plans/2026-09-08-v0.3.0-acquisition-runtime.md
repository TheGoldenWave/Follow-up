## 关键契约决策

1. **Signal Batch JSON 字段采用 snake_case**（`schema_version`、`batch_id`、`source_status` 等），与 design doc 一致；Python 是契约所有者，Node 消费端（后续 Task 18）负责映射到其内部 camelCase。既有 `candidate-feed`/`central-feed` 契约继续使用 camelCase，二者并存、互不改写。
2. **Schema 版本 `1.0`**；来源状态分类固定为 `ok` / `no-results` / `partial` / `rate-limited` / `auth-failed` / `unreachable` / `timeout` / `schema-drift` / `skipped-unconfigured` / `error`。
3. **脱敏在契约层强制**：Signal Batch 顶层与 item 均 `additionalProperties: false`；`contracts.py` 额外递归扫描禁止的凭据键名（`authorization`、`cookie`、`token`、`api_key`、`secret`、`password`、`bearer`、`credential`、`qr`、`phone`），命中即拒绝。
4. **`no-results` 是唯一“成功但无结果”的状态**；其余失败状态不得被表述为“该来源没有更新”。

## Fixed Assumptions

- Python 拥有采集层；Node.js 继续拥有 Digest 准备与投递。
- 受控 vendor 快照优先于 Git subtree 与零散复制。
- 免登录来源默认开；需凭据来源默认关。
- 文本/转录 7 天、候选元数据与用户状态 90 天缓存。
- 付费 Newsletter 全文不持久化。
- 中心 Feed 在本地采集通过验收前仍是运行时现状；本版本全部本地采集仅 shadow mode。
