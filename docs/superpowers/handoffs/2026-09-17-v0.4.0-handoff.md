## 6. Hugging Face Papers 关键恢复契约

实现文件与测试建议：

- `src/follow_up_acquisition/adapters/hugging_face_papers.py`
- `tests/acquisition/test_hugging_face_papers_adapter.py`
- `tests/acquisition/fixtures/hugging-face-papers/`

需要保持的硬约束：

- 网络 allowlist 为 `allowed_hosts={"huggingface.co"}`、`allowed_paths={"/api"}`。
- 只请求 `structured_endpoint`；`page_base_url` 只进入 provenance。
- 三视图 URL 必须显式使用 `zoneinfo.ZoneInfo`：
  `daily` 为 `/papers/date/<YYYY-MM-DD>`，`trending` 为 `/papers/trending`，
  `weekly` 为 `/papers/week/<ISO-WEEK>`。
- 每周格式使用 `date.isocalendar()`，示例为 `2026-W38`。
- 输入 JSON 接受顶层 list 或 `{"papers": [...]}`。
- 论文身份优先使用 `normalize_arxiv_id(...)`，其次使用 canonical `/papers/<id>` 生成
  `hf:<id>`，最后使用 canonical URL；不使用 DOI 或标题/作者 fallback。
- 三视图合并顺序固定为 `daily`、`trending`、`weekly`，每视图只保留第一个有效 evidence。
- evidence 使用固定顺序输出，丢弃无效 `rank`、`upvotes`、`github` 和不合法 views；
  无有效 evidence 或 UTF-8 JSON 超过 4096 bytes 时保留 candidate，并增加
  `hf-community-evidence-dropped` warning。
- stream ID 固定为 `daily`、`trending`、`weekly`，每个成功视图都生成 checkpoint。
- 状态矩阵为：全部成功且有候选为 `ok`，全部成功但为空为 `no-results`，
  部分成功为 `partial` 且 code 为 `hf-view-partial`，全部失败为 `error` 且 code 为
  `hf-views-failed`。
- 状态摘要消息精确为 `daily=<status>; trending=<status>; weekly=<status>`。
- candidate 的 `source_type` 固定为 `paper`；日期可解析时 `date_confidence` 为 `exact`，
  否则为 `unknown`。
